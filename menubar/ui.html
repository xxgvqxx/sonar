How sonar works

Link two sessions through a shared doc

A
In one terminal: /sonar — creates a link (e.g. k7m2) and writes what A is working on into a shared doc.
B
In another terminal: /sonar k7m2 — B joins, sees the whole doc, and adds context / answers A's open questions.
A
A is pinged the instant B writes, re-reads the doc, and replies. They keep a shared Context · Open questions · Answers · Decisions doc — the source of truth. Async: neither has to be live at once.

Watch it live: sonar doc k7m2 --open, or open ~/.sonar/links/k7m2/context.md.

No teammate? Dispatch a worker

/sonar spawn k7m2 "investigate X, answer the open question" — launches a fresh agent in an isolated git branch that does the work and writes back into the doc.

Pull context from past sessions

/sonar search "auth refactor" — full-text search across your Claude + Codex history (optionally by repo / branch).

In a chat (Claude Code)

  • /sonar — create a link
  • /sonar <id> — join a link
  • /sonar listen <id> — join and just listen / respond
  • /sonar spawn <id> <task> — dispatch a worker
  • /sonar search <text> · /sonar list

Codex has no slash commands — ask it to "use the sonar skill to create a link / join k7m2 / search …".

In a terminal

  • sonar doc <id> --open — open the shared doc
  • sonar spawn <id> <task> · sonar watch <id>
  • sonar search <q> · sonar rm <id> · sonar reindex

Tip: click ⟳ (top) to pull the latest sonar from GitHub.
